# CSS Strategy

Every page loads one stylesheet, `index.bundle.*.css`, through a normal,
render-blocking `<link rel="stylesheet">` in its `<head>`. None of it is
inlined into pages; the page template only carries a few small inline rules
for JavaScript and `<noscript>` fallbacks.

The stylesheet is render-blocking on purpose: a page never paints without its
complete styling, so there is no flash of unstyled content, and styling works
without JavaScript. The cost is waiting for the stylesheet on an uncached load.
After that, the browser caches it across page navigations.

Inlining a "critical" subset of the stylesheet would not let a page paint any
sooner, because the browser still waits for the blocking stylesheet. It would
add the same CSS to every page and push the `<meta charset>` declaration out of
the first 1024 bytes that browsers scan to detect a document's encoding.

## Head order

`<meta charset="UTF-8">` is the first element in `<head>`. The build inserts
these tags immediately after it, in this order:

1. The KaTeX stylesheet, only on pages that contain math (see [Math](math.md))
2. Font preloads for the configured default font pairing (see
   [Fonts](fonts.md))
3. The stylesheet

The stylesheet precedes the inline appearance-preference script, so its
font-face declarations are available to the font-loading barrier before a
stored font preference is applied. The JavaScript bundle is loaded with
`<script defer>` at the end of `<head>`.

## Bundle names

CSS and JavaScript bundle filenames include the Tada package version, for
example `index.bundle.tada-1.13.4.css`. When a site is regenerated by a newer
Tada version, pages point at different bundle filenames so browsers do not keep
using stale runtime assets from the older generator.
